# Weekend Flight Database v8.0 RC1 — GitHub-first

**Нове покоління Weekend Flight Optimizer.** Вебпанель українською; код у GitHub; публікація з GitHub у Cloudflare Worker; постійна SQL-база Cloudflare D1. Користувачеві не потрібно встановлювати Python, Node.js або працювати з командним рядком.

**Важливо:** це **release candidate**, що пройшов локальні інтеграційні тести з імітованими відповідями API. Live OAG, AirLabs, AeroDataBox та SerpApi потребують ваших власних ключів і подальших приймальних перевірок. Публікація в GitHub/Cloudflare сама не виконана: репозиторій і Worker потрібно створити в акаунтах користувача за інструкцією.

## Як усе пов'язано

- **GitHub:** вихідний код, Pull Requests, історія версій, автоматичні тести `.github/workflows/ci.yml`.
- **Cloudflare Worker:** серверний JavaScript, єдина панель, API-провайдери, AES-GCM шифрування ключів, перевірка OAG HTTP Push.
- **Cloudflare D1:** регулярні рейси, сезонні періоди, точні винятки, дельти, цінові спостереження, календарі, квоти. У D1 зберігається **робоча база**, а не в GitHub.
- **Cloudflare Cron:** одна сторінка черги щонайменше раз на 15 хвилин, якщо є активні ключі й бюджет; добові перевірки цін у вільний час.
- **Безкоштовні/пробні провайдери:** реалізований AirLabs Routes, OAG Schedules/HTTP Push, AeroDataBox (адресний flight verification), SerpApi Google Flights (ціни). Профілі інших провайдерів можна зберігати, але **не** заявлено live-конекторів для FlightAware/Cirium/Aviationstack/Duffel.

## Можливості, які вже є в коді

1. Регулярні розклади без первинного обмеження Friday/Sunday; сезонні правила та unknown-season маркери.
2. Повний двосторонній набір UK-аеропортів: departures + arrivals; Лондон може повертатися до іншого лондонського аеропорту, регіональні — до того ж самого.
3. AirLabs Routes із пагінацією, збереженням offset і поетапним збором; OAG Schedules за ефективним періодом, OAG HTTP Push signed delta.
4. Кожний OAG instance event змінює **датований виняток**, а не випадково всі п'ятниці; зміна effective-rule створює ревізію, включно з вилученням.
5. Багато профілів власників ключів, зашифровані секрети, індивідуальні ліміти та спільні ліміти груп, ручна заміна ключа.
6. Перевірка номера рейсу на конкретну дату через AeroDataBox за наявності доступу; відсутність у відповіді ≠ скасування.
7. Live-ціни SerpApi за вказаними аеропортами/датами; збережені цінові пороги, періодичні спостереження та записи `PRICE_TARGET_REACHED` у системному журналі.
8. ICS імпорт для Анни/Саші: all-day події блокують кандидатів; часові події показуються, але **потребують ручного перегляду**.
9. Односторонні кандидати та same-foreign-airport weekend pairs, локально з каталогу; експорт повного регулярного каталогу по сторінках CSV.
10. Імпорт експортованих CSV з v7 через браузер.

## Що не слід вважати завершеним

- **100% глобальне покриття** всіх авіакомпаній не може бути доведене без порівняння з незалежним повним еталоном і прав OAG.
- **Повністю автоматичне налаштування OAG HTTP Push підписки** неможливе без активації OAG Support. Реалізований серверний приймач після підключення.
- **Гарантована доступність рейсу/тарифу** не випливає з розкладу; потрібна повторна перевірка продавцем.
- **Push/email сповіщення** не налаштовані; пороги відстежуються в D1 та журналюються у панелі. Відправку email можна додати за окремим провайдером.
- **Пряме Google Calendar OAuth** не підключене: нині ICS-імпорт, причому складні RRULE/EXDATE потребують розгорнутого експорту.
- **Наземні перевезення та open-jaw між різними іноземними аеропортами** лишаються наступним етапом.
- **Повне синхронне завантаження даних із старої SQLite у Cloudflare** неможливе прямим підключенням локального файлу; передбачений імпорт CSV із панелі.

## Безпека

- Секрети не зберігаються в GitHub, у клієнтському JS або в URL браузера.
- API-ключі зберігаються в D1, зашифровані через AES-GCM із серверним `ENCRYPTION_SECRET`.
- Вхід: серверний пароль, підписана HttpOnly Secure SameSite=Strict cookie, обмеження невдалих входів.
- OAG HTTP Push: HMAC-SHA256 перевірка оригінального тіла, часу й ідентифікатора доставки.
- Cloudflare Access додатково рекомендований для членів сім'ї.
- Не розміщуйте робочу базу, API-ключі чи `.env` у репозиторії. `.gitignore` захищає основні форми таких файлів.

**Далі:** прочитайте `docs/DEPLOY_UA.md`, створіть окремий приватний репозиторій у GitHub Desktop, D1 у Cloudflare і зв'яжіть репозиторій через Cloudflare Workers Builds.
