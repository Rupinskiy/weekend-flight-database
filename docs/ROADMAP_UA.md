# Наступні етапи після live-підключення

1. **Повний контрактний тест OAG:** підтвердити, що Schedules API через конкретний key повертає всі сезонні графіки за аеропортом, коректно обробити 100% його paging і відмінності schema; підключити підписки HTTP Push за всіма напрямками UK.
2. **Незалежна верифікація покриття:** порівняння OAG із AirLabs, переліками аеропортів і перевізників; зазначення не тільки знайдених авіакомпаній, а й того, які пропущені й чому.
3. **Календарі:** Google OAuth + інкрементальна синхронізація, ICS RRULE / EXDATE / RECURRENCE-ID, час до/після заняття, груповий перетин Анна/Саша/сім'я.
4. **Наземний транспорт:** FlixBus GTFS + доступні GTFS залізниць, макс. 180 хвилин, лише зв'язки між аеропортами, розрахунок нічного очікування і доїзду до вокзалу; ціни необов'язкові.
5. **Open-jaw:** комбінації різних foreign arrival/departure airports, перевірка реальних наземних з'єднань і корисного часу.
6. **Long-haul:** інша топологія маршруту, 5–21 день, layover/self-transfer, календарі канікул.
7. **Ціни:** крос-перевірка SerpApi vs Duffel vs продавець, нормалізація багажу, можливий email/push через окремий провайдер.
8. **Production QA:** Playwright браузерні тести на staging, Cloudflare test binding D1, observability, захист від concurrent scans, Cloudflare Access, backup/restore D1.

GitHub workflow: одна зміна = окрема гілка/PR → CI → code review → merge `main` → Cloudflare deploy. Результати роботи D1 не зливаються через git pull: історія даних ведеться в D1 і копіюється резервними знімками окремо.
